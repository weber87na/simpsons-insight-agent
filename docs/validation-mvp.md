# 服務問題與小型實驗驗證 MVP

此功能從既有改善計畫出發，設計最多三項驗證實驗。支援校園服務及通用企業；所有模型根因都是假設。結果採人工資料與確定性規則，不使用模型判斷成功。

## 升級及啟動

關閉應用程式，備份營運資料庫，再更新套件及執行加法 migration `0006_validation`。不要直接將測試資料庫覆蓋營運資料庫。

```powershell
uv sync --no-editable --reinstall-package simpsons-insight-agent
uv run --no-sync alembic upgrade head
uv run --no-sync simpsons-insight-agent
```

新 migration 新增三張表；不改寫報告、原決策或改善工作。`0001` 在全新安裝時使用當前模型建表，因此 `0006` 也相容已存在的新表。應用程式僅接受最新 schema，避免漏升級時默默失敗。降版會刪除新驗證資料，請先備份；一般升級不需降版。

## 無付費模型的合成示範

```powershell
uv run --no-sync python scripts/seed_validation_demo.py --database data/validation-demo.db
$env:DATABASE_URL = 'sqlite+aiosqlite:///D:/simpsons-insight-agent/data/validation-demo.db'
```

種子腳本拒絕覆寫既有檔案。執行後輸出報告網址，並保存同名 JSON manifest。資料為自寫校園服務合成文字，模型由固定替身取代；品牌名稱明示「非高科大真實評論」。已保存一項通過合成審查的草稿供操作，不能用來驗證模型準確度。切回原資料庫前，關閉程式並在此終端移除 `DATABASE_URL` 環境變數。

## 操作流程

1. 在報告底部找到「小型實驗：先驗證，再決定」。原決策必須結束，且問題引用確實存在於本報告。
2. 選校園或企業情境，填入實驗開始日、專用每週工時及限制，按「設計小型驗證實驗」。正式生成沿用原任務模型設定，需要有效金鑰。原決策不會變動。
3. 查看服務階段、假設、替代解釋、支持／相反證據與審查理由。沒有相反證據不代表根因已證明；零項實驗代表應查看待補資訊。
4. 於草稿確認指標名稱、類型、單位、增加／降低方向、絕對改善門檻、每期最低樣本數及前後日期。門檻和樣本數不預填。比例門檻為百分點，例如 60% 到 70% 是增加 10 百分點。
5. 勾選確認並開始。開始後量測規格鎖定，不能退回草稿。審查未通過的實驗不可開始；可以停止。
6. 人工回填前後成功數／總數，或平均值／樣本數，並填可比較性及干擾因素。缺資料可以留空，但零樣本數不可輸入。
7. 保存後立即顯示規則判讀。修正資料要新增回填，保留原紀錄；相同提交識別碼及內容不重複新增。觀察結束且至少回填一次後可標記工作完成；工作完成不代表成效達標。

指標確認可修正模型建議的量測方式；步驟、工時及證據屬已審查設計，MVP 不提供任意改寫。完成或停止的已啟動實驗仍能追加更正結果，規格繼續鎖定。草稿直接停止者不可回填。

## 判讀規則

規則版本為 `descriptive-v1`，以台北 UTC+8 日期為準，觀察結束日當天仍屬觀察中，次日才視為期間完成。

| 順序 | 條件 | 結果 |
| --- | --- | --- |
| 1 | 缺必要值，或任一期樣本低於使用者門檻 | 資料不足 |
| 2 | 觀察期間未結束 | 觀察中 |
| 3 | 有干擾因素，或前後不可比較 | 需人工判讀 |
| 4 | 方向性差值達到絕對門檻 | 達到預設目標 |
| 5 | 其他 | 未達預設目標 |

結果只代表使用者門檻是否達到，沒有統計顯著性或因果結論。規則以 Decimal 計算差值門檻，避免浮點邊界誤判。歷史保存當時判讀日期，不因隔日閱讀自動改寫；若需重新判讀，新增回填。

## Agent、證據及資源邊界

- 證據以完整報告快照為準，不沿用畫面圖表篩選。先保留原問題引用，再按相關面向／主題、來源及週次輪流選取；未知日期獨立分組。最多60筆、每筆800字，顯示涵蓋資訊。
- 未入選的原引用不送模型；模型只能引用本次匿名鍵。支持、反證都檢查白名單，支持必須連到原問題證據；同筆不可同時作為支持與反證。
- 兩階段為驗證設計與獨立審查，最多一次設計修訂。每階段最多120秒、最多三次嘗試，整次最多600秒；完成的階段保存後不重跑。失敗／取消可續跑，停機恢復未完成流程。
- 工時池獨立於原改善工作。排程只算投入工作，不將被動觀察天數當成人工作時；日期或工時未填時提供相對草案，不猜實際班表。
- 未知費用保存為空值，不代表免費。保留模型、用量、耗時、錯誤種類及嘗試紀錄；不新增付費價格查詢。
- 一個改善計畫只有一個驗證流程，重複建立回傳原流程；需要全新設計時以新報告及其改善計畫開始。沒有自動重新規劃、外部寄送或派工。

## API

| API | 用途 |
| --- | --- |
| `POST /api/decisions/{id}/validation` | body：context=campus或business、start_date、weekly_hours、constraints；回202與id |
| `GET /api/decisions/{id}/validation` | 尚未建立回id=null；已建立回狀態、coverage、stages、實驗及歷史 |
| `POST /api/validations/{id}/cancel`、`/retry` | 取消／接續；重試不覆寫已完成階段 |
| `PATCH /api/validation-experiments/{id}` | measurement保存量測規格；status變更工作狀態，開始需confirmed=true |
| `POST /api/validation-experiments/{id}/results` | submission_id、before、after、comparable、confounders、notes；回201與判讀 |

Measurement：metric、metric_kind=ratio或mean、unit、direction=increase或decrease、threshold、minimum_sample、before_start、before_end、after_start、after_end。
Observation：count及successes（比例），或count及mean（平均值）；未提供的數值可省略。日期需依序且前後不得重疊。不合法輸入回422，規格鎖定、未審查通過等狀態衝突回409。

## 真實高科大案例的後續驗證

先定義單一校區或服務範圍、品牌別名、來源及期間，使用既有蒐集功能建立新報告，人工抽查相關性。完成原決策後才設計實驗。請由服務承辦人核對實際文件、流程、可用人力及成效量測方式；不要把合成示範的步驟與門檻當成校方實況。

真正效果驗證需人工取得服務完成數或等候時間；評論數不等於申請件數。記錄學期、申請尖峰與同時變更的措施。可比較單 Agent 與此流程的證據支持、實用性、成本與耗時；本次離線／瀏覽器測試不替代真人研究評估。
