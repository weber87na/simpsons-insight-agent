# OpView 功能差距與店家／品牌營運補強方案

日期：2026-09-07。使用者選定情境：店家／品牌營運。建議先補「查得準、看得懂、追得到證據、交得出報告」，沿用既有改善計畫。

**更新：P0～P2 已依 M1～M5 實作，見[營運分析使用與驗證](operational-analytics.md)。以下保留實作前差距盤點，不能視為目前仍缺少的功能。** 現況以本次工作目錄（含未提交的決策升級）為準。「已有」指程式碼存在，不代表本輪執行過系統測試。網站操作與限制見 [探索紀錄 E01–E15](opview-benchmark.md)、[58張桌面截圖](opview-ui-reference.md)。最新介面、資料流、API／型別與逐項驗收見[詳細實作規格](opview-implementation-spec.md)；API與操作方式以營運分析文件為準。

## 功能對照

第二輪 N1～N5 已補上自訂議題比較、情緒／來源分布、完整排行與排序、品牌證據連動、圖檔下載及比較CSV／列印。最新操作、API與驗收結果見[議題與品牌比較文件](comparison-workspace.md)；下列差距表繼續保留為研究歷史。

## 程式碼依據與 P0：統一口徑

- [insights.py](../src/simpsons_insight_agent/insights.py)：`trends` 支援週／月；`snapshot_items` 優先取快照，舊報告無快照時讀資料表。快照缺標題、看板、討論串、URL 及互動等部分中繼資料；`keywords` 是主題重點抽取。
- [api.py](../src/simpsons_insight_agent/api.py)：`get_report_reviews`、`export_report` 讀目前 `Review`／`ReviewAnalysis`；明細可篩選來源、內容類型、情緒、星等、面向及文字，匯出未共用篩選。
- [insight_api.py](../src/simpsons_insight_agent/insight_api.py)：趨勢與證據取快照；比較 API 已回傳 `trends`、`complaint_aspects`、`common_complaint_aspects` 及來源／期間限制。
- [models.py](../src/simpsons_insight_agent/models.py)、[報告模板](../src/simpsons_insight_agent/templates/report.html)、[趨勢介面](../src/simpsons_insight_agent/static/insights.js)：確認資料欄位、熱門討論串、週／月圖表與證據對話框。

「圖表、明細、匯出讀取路徑不同」是已確認的程式碼差異；續抓造成呈現不一致是由此推得的風險，後續實作已加入更新底層Review後快照不變的離線測試。

P0 為 P1、P2 的前置工作：

1. 新報告擴充版本化快照，保存標題、看板、討論串鍵、來源 URL、平台互動資料及目前商家標籤。文字與標題維持遮罩，不新增作者原文或匿名鍵的公開／雲端輸出。
2. 圖表、明細、證據、匯出共用資料集及日期、來源、內容類型、情緒、面向、主題、文字篩選；保留星等與單筆 ID 查詢相容性。
3. 舊快照缺欄位即標示不可用。無快照的舊報告保持可讀，但明示為舊版資料表讀取；不原地改寫，也不以現存中繼資料冒充歷史欄位。
4. 樣本按內容 ID 去重；討論串按來源＋討論串鍵計數；平台互動獨立呈現，缺值不是零，不混入情緒分母。
5. 一般明細可顯示日期精度不足項目；圖表下鑽與對應匯出須沿用該圖精度規則並列排除數，讓總數可對帳。

完成門檻：新快照不受後續來源資料更新影響；相同條件與精度規則下，圖表、明細及匯出一致。若後續需 migration，採加法升級並先備份；本輪不新增 migration。

## P1：營運分析主流程

- 趨勢增加日粒度、正／中／負筆數、P/N 比與來源序列。台北時區，日粒度只接受 day 精度；週／月沿用現行規則。空桶補零，零分母比例回傳空值。
- P/N = 正面筆數 ÷ 負面筆數；負面為零時回傳空值與原因。僅星等與未知分類不進入文字情緒分母。
- 點日期、情緒或來源，以相同條件開啟快照明細與證據；保留相關主題與改善工作引用入口。
- 新增來源／看板排行。Google 無細分資料時使用目前商家，不推定分店；缺看板列為未知頻道並顯示缺失數。
- 提供「包含任一詞、必須包含、排除詞」欄位：任一組內 OR，必須詞全符合，排除詞任一命中即排除，組間 AND；空組不限制。比對遮罩後標題與文字，不直接執行任意運算式。
- 查詢只調整已蒐集樣本，不自動擴大爬取。資料不足、來源失敗及估計日期提示保留。

建議介面：`GET /api/reports/{id}/trends` 增加 `day|week|month` 與統計欄位；明細／匯出接共用篩選；新增 `GET /api/reports/{id}/channels`。保留既有欄位、路由及 Google-only 任務 body。新型別與 API schema 草案已列於詳細規格，後續開發需依相容測試定稿；這些新增能力目前尚不可呼叫。

完成門檻：找出負評增加期間 → 辨識來源 → 回查同批證據 → 查看相關改善工作；基本統計不依賴付費模型。

## P2：探索與報告交付

- 全體／正面／負面關鍵詞排行附詞頻與證據，文字雲使用相同資料。公開斷詞、停用詞及計分版本，不複製未知的 OpView 權重／擴散公式。
- 重用品牌比較已有回應，在共同期間同步顯示趨勢及共同面向表；保留來源、精度、期間與完整度差異，不推定市場占有率。
- 新增可列印報告頁及趨勢 CSV，包含条件、樣本限制、圖表、證據摘要及改善工作；使用者可另存 PDF。若改善計畫基於完整報告，明示其範圍與當前篩選不同。
- 維持本機運作，不建立公開分享 URL、權限系統或外部寄送。

完成門檻：報告可閱讀、可追溯，數字與畫面一致；比較重用已有統計口徑。

## 驗收要求與暫緩項目

以下為原驗收要求；實際執行範圍見營運分析文件：

| 類別 | 案例與預期 |
| --- | --- |
| 一致性 | 修改底層評論後，新快照不變；篩選後圖表、明細與匯出可對帳 |
| 時間 | 台北跨日、週一起算、跨月、空期間、未知與粗粒度日期，排除數可解釋 |
| 情緒 | 無負面、無分類、僅星等、未知分類；比例無除零或無限大 |
| 來源與去重 | 重複內容、跨來源同名討論串、互動缺值、來源部分失敗，各指標不混算 |
| 查詢 | 任一／必須／排除詞組合、中文與符號、空條件、不合法條件；錯誤清楚且無查詢注入 |
| 操作 | 離線合成餐飲資料走完「期間 → 來源 → 證據 → 改善工作 → 匯出」，下鑽保留條件 |
| 相容 | 舊報告可讀且標示限制、既有 API 與 Google-only body 可用，無金鑰有基本統計 |
| 交付 | 列印圖表不截斷，條件與限制完整，CSV 可對帳，遮罩不洩露作者資訊 |

定期蒐集／危機通知、新聞與社群新來源、人口族群推估另案研究。它們需額外來源可用性、服務運作及資料方法設計；本次也未驗證 Trend 的預警能力。保留 FastAPI、SQLite、現有三平台邊界與所有未提交修改，不在文件工作中啟動爬取、付費模型或改動營運資料。
